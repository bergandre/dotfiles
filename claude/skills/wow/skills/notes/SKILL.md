## Layout
- `characters/<Char>/<Char>.md` — character hub: level, spec, links; its `## Catch-up` table
  (profession skill vs target, next gear) is the single source of the numbers
- `characters/<Char>/<Spec>/Leveling.md` — talents, rotation, group/duo, Forever changes; links to gear notes
- `characters/<Char>/<Spec>/Weapons.md` — gear **options** per level band (tables: option, DPS,
  stats, req, source incl. own Blacksmithing, Got), not a 100% checklist; e.g. `Arms/Weapons` / `Prot/Weapons`
- Spec notes live in `characters/<Char>/<Spec>/` with plain names (Leveling, Rotation, Talents, Weapons) —
  names repeat across specs, so link them by full vault path with an alias:
  `[[Wow_FOREVER/characters/Karums Warrior/Prot/Talents|Prot talents]]` (pipe escaped in tables)
- `characters/<Char>/<Spec>/Talents.md` (+ `Rotation.md`) — generated talent trees with hover (`wow:talents` skill)
- Crafting professions: `professions/<profession>/leveling.md` + generated `recipes.md` + `materials.md` (layout and
  rules in profession-plan/SKILL.md; link by full vault path + alias); gathering: `professions/<profession>/<profession>.md` + `maps/`
- `professions/merchants-favor.md` — shared Favor mechanics and crate inventory
- `professions/profession-benchmarks.md` — generated by gather-zones
- `catchup/catchup.md` — lean hub: embeds each `![[<Char>#Catch-up]]` + links; level plans (`PLAN40.md`) live there too
- `items/` — one card note per item (any type), icons in `items/icons/`
- `abilities/` — one card note per NPC/boss spell (in-game spell tooltip), icons in `abilities/icons/`
- Item and ability notes are shared — reuse if it exists, never duplicate
- Todos live in TickTick (ticktick:add), never in the vault — don't add or tick todo lines in notes

## Style — cheatsheet, not a report
- `#` title with who/what (e.g. "Horde Arms duo", "Cooking — Karums Warrior (Horde)")
- `##` sections, one-line bullets, `level — what`; chains with `→`
- No sources, no "unverified", no prose, no why-explanations
- Notes are for the user only: no meta lines (how the note/hover works, legends, "generated by", data
  sources beyond one link, "update numbers there"). Knowledge for future AI sessions goes into this plugin's
  SKILL.md files (and repo CLAUDE.md), never into vault notes — one exception: the `## Notes for future sessions`
  section at the very bottom of a profession's leveling.md (the user asked for it, 2026-11-24)
- Only what was established in the conversation — don't fill gaps
- "Modernize" a note = keep every fact and checkbox state, only change formatting

## Items, abilities, NPCs in text — ALWAYS inline icon + link (hover = card, click = opens it)
- Every mention of an item, a spell/ability/talent or an NPC (vendor, trainer, quest giver, boss) is a link
  to its card — no plain names. Missing card → make it first:
  items `gen_cards.py`, abilities `gen_abilities.py --by "Warrior"` (player) / `--by "<Boss> (<Dungeon>)"`,
  NPCs `gen_npcs.py <vault>/npcs <id> … [--boss <id> …]` (ids: Zygor `Name##id`, NPCData comments,
  ForeverDungeonJournal `npcID`)
- Same thing already expanded on the page (a `## Name` section, boss banner) → link there instead:
  `[[#Name]]` (Obsidian jumps); in HTML blocks `data-wm-open="<Card>"` (wowmap-jump plugin: jumps to a
  `[data-wm-id]` on the page, else opens the card)
- `python3 -I linkify.py [--dry] <note.md> …` links all plain mentions that have a card (player abilities only,
  `ALIASES` for the user's shorthand like "Imp Rend"); run it after writing a note
- Card names that clash get ` (<id>)` (e.g. `Shield Slam (23922)` next to a boss's `Shield Slam`) → link with
  alias `[[Shield Slam (23922)|Shield Slam]]`
`![[<icon>|inline]] [[<Note Name>]]` — icon from the item note's `icon:` field
- Caption must be exactly `inline` (theme opt-out from image gallery/centering); size comes from wow.css
- Alias when shorter/plural reads better: `[[Bristle Whisker Catfish|Catfish]]`
- Recipes: note is `Recipe - X.md` (Obsidian forbids `:`)
- Hover in edit mode: `gaming/.obsidian/page-preview.json` = `{"editor": false}` (Page preview core plugin,
  per-source "require Ctrl"; Obsidian's default for the editor is true) - set 2026-11-21, so links hover
  everywhere, not only in tables. HTML blocks (wowmap, wowtal) carry their own CSS hover cards
- Inside tables escape the pipe: `![[icon\|inline]]`, `[[Name\|alias]]`. Tables can't hold task checkboxes: use a
  "Got" column (✓) instead

## Gear note (`<Spec>/Weapons.md`) — options, not a checklist
```
# <Spec> weapons — <type> (e.g. Arms (2H))
- Pick — <one-line rule> 
- Now — <equipped item link> · **BS** → [[blacksmithing]] · [[Wow_FOREVER/characters/<Char>/<other spec>/Weapons|<other spec> weapons]]

## <level band> — now
| Option | DPS | Speed | Stats / effect | Req | Source | Got |
|---|---|---|---|---|---|---|
| <icon link> | 38.8 | 3.6 | +20 Str, +10 Sta | 39 | <dungeon> — <boss NPC link> / quest / **BS** 190 |  |
```
- Candidates come from the scanner, never from memory or a by-eye pick:
  `python3 -I gear_options.py --char "<Char>" --role W|P --slot 2h|1h|shield|<slot> --min <lvl-5> --max 60 --note "<vault-relative Weapons.md>"`
  Scans ForeverDungeonJournal (boss + trash loot, dungeon quest rewards incl. follow-ups, SharedLoot) + every
  AtlasLoot Forever loot table; drops wrong-faction quests (Bonebiter's is Alliance-only) and items the class
  can't use; scores with `loot_note.score()` (AP, Sta, hit, crit count, not only Str/DPS; Arms 2H = white DPS
  + avg hit for Mortal Strike / Overpower / Whirlwind, so slow weapons win at equal DPS - user's rule); lists
  everything that beats the worn item. Procs: guessed 1/min (`PROC_PPM`), AoE ones (Ravager) x2 mobs
  (`AOE_TARGETS`, the duo pulls several)
- Every `MISSING` line (scores ≥ the band's median option, items below the first band count as "now") is either
  added or rejected on purpose (e.g. dungeon far above the band); re-run until only rejects are left
- Rows in each band sorted by that score, best first (the user's "how dope" order)
- 3–6 options per band is a reading aid, not a cut: a higher-scoring option never gets dropped for a weaker one
- Not in the scan (check by hand): zone/class quest rewards (Whirlwind Axe), world drops, vendors, own
  Blacksmithing (`professions/blacksmithing`)
- Re-run after leveling into a new band, after a ForeverDungeonJournal update and after a dungeon note
  (its W/P upgrade lines are often the first sighting)
- Missed before (2026-11-21, why the scanner exists): Ceremonial Mallet (Drowned City follow-up quest, +22 AP
  read as "only +15 Sta"), Mograine's Might (in the SM Cathedral note, never copied here), Bloodied Gutslicer -
  the old scan had found them, the hand-picked shortlist dropped them

## Enchants note (`characters/<Char>/Enchants.md`)
- Tables: slot (worn item link) | enchant card | effect | mats with item links | ≈ AH cost | Got; sections
  "Buy now — best first" / "Worth it if an enchanter has it" / "Skip at <lvl>"; one shopping-list line
- Forever enchants are applied in person (trade window), no scrolls → cost = AH mats + tip
- Effect + reagents from the Wowhead Forever spell tooltip (`nether.wowhead.com/forever/tooltip/spell/<id>`),
  never Classic memory: Forever changed numbers and mats (2H Impact = +6 for 2 Vision Dust + Large Glowing Shard)
- Spell ids: AtlasLoot `AtlasLootContinued_Crafting/data-forever.lua` (`EnchantingForever`; Forever-only
  formulas like 2H Lesser Strength / Necklace Strength sit in the "Skill …" blocks as `Formula: …` 12xxxxx ids)
- Cards: `gen_abilities.py <vault>/abilities --by "Enchanting" <spell ids>` (Forever renames: Chest Superior
  Health = "Superior Stamina"); reagents `gen_cards.py`
- Prices: `tsm-analyze.py --item <id>` - look shards up **by id** (names are wrong in local data):
  Large Glimmering 11084, Small Glowing 11138, Large Glowing 11139, Small Radiant 11177, Large Radiant 11178
- What's already on worn gear: enchant id = 2nd field of the BagBrother link (`2870:8484:…`) →
  `nether.wowhead.com/forever/tooltip/item/<item>?ench=<id>` shows its text
- Low-level gear about to be replaced → only one-dust enchants; gold goes on the weapon

## Profession note
- `## Progress` — checklist: `- [ ] <from> → <to> — <inline items> ×N (notes)`
- Trainer/book steps as their own checklist line (e.g. `125 — Expert Cookbook — <vendor>`)
- `## Recipes to get` — checklist line = where to buy, card under it:
  ```
  - [ ] Tari'qa, Crossroads
    ![[Recipe - Strider Stew#^card]]
  ```
- Shopping / Mats / tips sections — bullets with inline items
- Shopping heading always carries the range and the catch-up price estimate: `## Shopping (200 → 225, ≈ 8g)`
  (gold still to spend to reach the target; owned mats = 0)

## Item cards
1. Get Wowhead Forever item IDs
   - Local data: `python3 tsm-analyze.py --item "<name>"` in the addon-settings repo → `(id N)`
   - Gear guides with item links: timesaver.gg leveling-gear, method.gg weapon lists
2. Generate — prints `id, note name, icon, quality`; skips existing notes, `--force` regenerates:
   `python3 -I ~/.claude/skills/wow/skills/notes/gen_cards.py ~/Documents/obsidian/gaming/Wow_FOREVER/items <id> …`
3. Check every printed name matches the item — local TSM data has wrong name→ID pairs.
   Wrong/missing → try the Classic ID and check the printed name; never use an unchecked ID
4. No ID found → stub card in `items/`, tell the user which:
   ```
   ---
   id:
   tags: [wow/item]
   ---
   > [!wow] <Item Name>
   > <type · stats known from research>
   > <span class="extra"><source></span>
   > [Wowhead search](https://www.wowhead.com/forever/search?q=<Item+Name>)

   ^card
   ```

## Styling
- A "Mats" column/cell always lists the actual materials with icon links (one per line in tables), never a gold
  estimate in their place (user rule, 2026-11-24)
- Items, recipes and abilities that are new in Forever (Wowhead shows the blue "NEW IN FOREVER" badge; list rows carry
  `envChange.status == "new"`) get `<span class="wf-new">NEW IN FOREVER</span>` right after their link, in every note
  (user rule, 2026-11-24; wow.css `.wf-new`)
- Money is always in in-game coin colours: `<span class="mg">1g</span> <span class="ms">24s</span> <span class="mc">5c</span>`
  (wow.css `.mg/.ms/.mc`); restyle a hand-written note with
  `python3 ~/.claude/skills/wow/skills/profession-plan/recipes_catalogue.py x --money <note.md>` (user rule, 2026-11-24)
- Cards = `> [!wow|<quality>]` callouts, inline icons = `|inline` embeds; both styled by
  `gaming/.obsidian/snippets/wow.css` (must stay in `appearance.json` → `enabledCssSnippets`)
- New tooltip parts → add a class to `wow.css`, don't inline styles
