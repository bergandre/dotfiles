# Dungeon note (WoW Forever)

Reference dungeon: `dungeons/Excavation Site - Wetlands/` (agreed format, 2026-11-17).

## Layout
One folder per dungeon `~/Documents/obsidian/gaming/Wow_FOREVER/dungeons/<Dungeon>/`. The main note is the only
file at the top; everything else sits in subfolders. Keep file names unique - Obsidian links by name.
```
<Dungeon>/
  <Dungeon>.md                 main note (hand-written + embeds) - section 4
  map/<Dungeon> map data.md    source: kill order, boss sections, trash lines, W/P upgrades (hand-written)
  map/<Dungeon> map.png        map image (cheatsheet.py / stitched floors / FDJ tga)
  map/<Dungeon> (interactive).md   generated by interactive_map.py - never edit
  notes/<Dungeon> loot.md      generated by loot_note.py - never edit
  notes/<Dungeon> quests.md    pick up / turn in - owned by the dungeon-quests skill
  art/                         portraits (<Boss>.webp), sketches, method/ renders (tactics.py)
```
**Wings** (Scarlet Monastery, Dire Maul...): one parent folder, a subfolder per wing, no prefix in file names -
pass `"Scarlet Monastery/Graveyard"` to every script -> `dungeons/Scarlet Monastery/Graveyard/Graveyard.md`,
`map/Graveyard map data.md`...; AtlasLoot / FDJ / site slugs use the full name ("Scarlet Monastery Graveyard").
The parent holds a hub note `Scarlet Monastery.md` (wing table, run order, key). Reference: `dungeons/Scarlet Monastery/`.
Shared: `abilities/<Spell>.md` ability cards (+ `abilities/icons/`, incl. `ej-<flag>.png`), `items/<Item>.md`.
There is no separate tactics note: the map's banners show the map data. Game data repo:
`~/repositories/wow-forever-addon-settings` (CLAUDE.md there: accounts, chars).

## Workflow
1. `fdj_map.py` (journal map + boss pins) / `cheatsheet.py` (bosses + loot vs worn gear) (section 1)
2. `tactics.py` - ability cards, guide text, art (section 2)
3. write `map/<Dungeon> map data.md` (section 3) incl. W/P upgrades (section 3b)
4. `loot_note.py` - loot note + `## Loot` embed in the main note
5. main note: frontmatter pins + **route** (required), TLDR (section 4); quests note via `dungeon-quests`
6. `interactive_map.py` - map + banners, `--preview` the route (section 5)
Done = route on the map, TLDR, map, loot, quests note.
Scripts live in `~/.claude/skills/wow/skills/dungeon-cheatsheet/`; run them with `python3 -I`.

## 1. Collect data
**Map + boss pins: the in-game journal first.**
```
python3 -I fdj_map.py "<Dungeon>" [--write]
```
ForeverDungeonJournal's map tab (`Core/Journal.lua` `FDJ.DUNGEON_MAPS`) has the author's in-game boss spots per
floor, the entrance, floor transitions (ladders, "Level 2") and NPCs inside - better than foreverchanges' pins
(Dalaran: Atrexis was on the wrong side). For dungeons with the addon's own art (Forever-only ones: Dalaran,
Excavation Site, Ruins of Lordaeron, Drowned City, Hall of Thanes, Blackmaw Hold, ...) it builds
`map/<Dungeon> map.png` (floors side by side, "Level n") and `--write` sets `map:` + all `kind: boss` pins in the
main note. Use its entrance / transitions as route anchors. `--write` needs the main note to exist (create a skeleton first) and writes names
unquoted: quote names starting with `"` (`'"Pyromancer" Braxton'`) or YAML breaks. Classic dungeons use the client's map tiles -> it only
prints positions (floor-local, not stitched). The addon ships those maps as `Media/Maps/<Name><floor>.blp`
(1024², map = top-left 1002x668; Pillow opens BLP): crop, paste small extra floors as an inset, `-resize 200%`
-> `map/<Dungeon> map.png` + `map:`; the printed pins are % of that 1002x668 area. Reference: `dungeons/Uldaman/`
(Level 2 inset). Else use cheatsheet.py's map.
```
python3 -I cheatsheet.py "<Dungeon>" [--slug <foreverchanges-slug>] [--chars "Karums Warrior,Karums Priest"] [--no-map]
```
- **Map**: downloads `foreverchanges.pro/dungeons/<slug>` map + boss pins, draws numbered red
  markers (numbers = boss path order) -> `map/<Dungeon> map.png`. Prints which bosses have no pin.
  Slug default = lowercased name with dashes; SM wings etc. may need `--slug` (check the site's URL).
  No web map -> falls back to local `InstanceAtlas/Maps/*.tga` (no markers). Always look at the PNG (Read) before using it.
  **Multi-floor** (script prints "N map images"; the site pins bosses on floor 1 only): download
  `<slug>-1..N.webp`, label each "Floor n" (`magick -annotate`, font via `fc-match`), stitch with
  `magick montage -tile 2x2 -geometry +0+0` over `map/<Dungeon> map.png`, set `map: <Dungeon> map.png` in the
  main note's frontmatter and give every boss a `kind: boss` pin (floor-local % -> grid: x=(col*100+x)/2,
  y=(row*100+y)/2). Draw the pins on a copy and Read it to check. Reference: `dungeons/Gnomeregan/`.
  **Forever-only dungeon** (foreverchanges 404, e.g. Excavation Site): in-game map from the ForeverDungeonJournal
  addon `<repo>/Interface/AddOns/ForeverDungeonJournal/Media/<Name>Map.tga` (1024² with a black bottom ->
  `magick ... -crop 1024x690+0+0 -fuzz 8% -trim`) -> `map/<Dungeon> map.png` + `map:` + a `kind: boss` pin per boss.
  method.gg's map is the mirror image of it (both fan recreations) - ask the user which matches the game.
  Names with `:` -> folder/notes use ` - ` (Obsidian forbids `:` in file names); scripts match AtlasLoot by letters only.
  `map:` is a file name; the scripts look for it in the dungeon folder, then in `map/`.
- **Bosses + loot**: Forever loot IDs from local AtlasLoot `data-forever.lua` (path order), item stats
  from Wowhead Forever tooltips (cached in `~/.cache/wow-tooltips`), and what each char wears in the
  matching slot from `BagBrother.lua` (refreshed on `/reload` or logout - ask the user to `/reload`
  if gear looks stale). Only items the class can equip are compared.

## 2. Abilities, guide text, art
```
python3 -I tactics.py "<Dungeon>" [--slug <slug>] [--force]
```
- method.gg Forever guide: every boss + important trash mob -> spell IDs -> ability cards in `abilities/`
  (`notes/gen_abilities.py`: Wowhead Forever spell tooltip, dispel type, "Used by: <mob> (<Dungeon>)").
  Prints each mob's guide lines and method's flags (e.g. `important` = the whole mob is dangerous).
  `! important` line = abilities the guide text stresses ("main mechanic", "dangerous", "deadly"...;
  no site tags single abilities) -> flag them `ej-important` (red frame); add others by judgement.
- warcrafttavern (Forever page, then Classic): intro + Tank / Healer / Damage Dealers text.
- art: foreverchanges portraits -> `art/<Boss>.webp`; DungeonJournal addon pencil sketch (few bosses) ->
  `art/<Boss> sketch.png`; method.gg model render per mob/boss tile -> `art/method/<tile>.jpg` (trash banners,
  portrait fallback); journal flag icons -> `abilities/icons/ej-<flag>.png`.
Wowhead's site 403s curl, the `nether.wowhead.com` tooltip API works. icy-veins 403s.
Rewrite the guide text for the duo (W tanks + deals damage, P heals); don't copy CC/kick advice that
needs other classes. Spell tooltips beat guide prose (e.g. Dominate Mind tooltip caps at level 25).

## 3. Map data (`map/<Dungeon> map data.md`)
Style of the `notes` skill: cheatsheet, no prose, no sources. Line 2 = the flag legend. Starts with
`## TLDR` (-> `map/<Dungeon> tldr.md`, embedded at the top of the main note):
```
- <4-6 bullets: what kills you here and what to do - boss order + which to skip, the dungeon-wide threat
  (disease/poison/fear/stealth packs), the pack to kill first, the hardest boss's key move, quest objectives inside.
  Role-general ("the tank"/"healer"). No level range / location / W-P legend lines - they carry no info>
```
Write every boss / trash mob as `**<Name>**` -> portrait chip that jumps to its banner (matched by shared words, plural
s ignored: `**Necromancers**` -> Kirin Tor Necromancer; no match = plain bold). Abilities as
`![[<icon>|inline]] [[<Ability>]]` -> hover icon. Under the bullets interactive_map.py adds **Big drops** by itself:
boss upgrades >= `BIG` % (40), empty slots and every weapon upgrade from `upgrades.json`, with the boss chip and the classes that would roll
Need (`loot_note.py` `rivals()`: armor/weapon type ∩ stats, minus W/P) - so the user picks the group around them
(wand wanted -> no warlock). Run loot_note.py first. Then `## Pulls — kill order` (shown as the numbered "Kill order" row above the trash banners):
```
Any trash pack, top first. You have no CC, so the kill order does the job of CC:
1. <inline icon> [[<totem/ability>]] or **<Mob>** — <why first>          <- totems, stunners, healers, mana burners, summoners, melee last
- **Casters:** LoS-pull ... / **Interrupts:** Pummel = Berserker Stance only / **<danger mob>:** <follow rule>
- **Boss packs:** kill order = that boss's **TLDR:** line
```
Guides list only the mob types, not what's in each pack (method.gg "Important Trash", warcrafttavern, Wowhead
Classic); the priority list comes from those. Don't make up pack compositions; add one only when the user
reports it. Then per boss in map order:
```
## <map nr>. <Boss> — <level> [(rare)] [(no map marker)]
> [!boss] <creature type> · <where / adds>
> [![[<Boss> sketch.png]]]
> <one-line overview>
> **TLDR:** <how to reach the boss if it is not obvious (barrier, portal, summon); then the fight: kill order / key move / what not to stand in>   <- banner + pin card show this line; never only the access part

- ![[<spell icon>|inline]] [[<Ability>]] ![[ej-<flag>.png|inline]] ![[ej-tank.png|inline]] — <cast time, what it does> → <who does what>

> [!roles]
> > [!tank] Tank · W
> > - ...                                    <- role-general: "the tank" / "the healer", not W/P
>
> > [!healer] Healer · P
> > - ...
>
> > [!dps] Damage · W
> > - ...

- [ ] W — ![[<icon>|inline]] [[<Item>]] — <why, vs what is worn>      <- upgrades (3b)
```
Level unknown (Forever-only bosses) -> drop ` — <level>`: anything but digits there becomes part of the boss name
and its pin no longer matches ("N without pin").
Then `## Trash` - one line per mob type, shown as a trash banner:
`- [ej-important] **<Mob>** — <point>, <icon> [[<Ability>]] <effect> → [ej-tank] <tank does>; [ej-healer] <healer does>`
(points split on ", " - no commas inside a point; actions split on ";", a leading role flag = shield/cross/sword
line, no flag = everyone), then trash upgrade lines. Optional `## Quest rewards`:
`- [ ] W — <Quest> — ![[icon|inline]] [[<Item>]] — why`.
**Flags** (journal icons, only when they matter): role flags = who must react (ej-tank shield, ej-healer cross,
ej-dps sword; corner badge on the ability icon), important (red frame; on a trash line = dangerous mob, listed
first with a red edge), interrupt, magic/curse/poison/disease (dispel type from the card), enrage, nonphys/physical.
Priest dispels Magic (Dispel Magic) and Disease; no poison/curse removal -> "heal through".

### 3b. Judge loot
From the cheatsheet.py output pick only real upgrades per char; skip side-grades. Rules:
The loot note computes this itself (approx % per char, below); hand-written lines are for the map's boss cards.
- Warrior = Arms 2H, levels as the duo's tank in Def/Battle stance: Str, 2H DPS, Sta, armor. No 1H/shields.
- Priest = healer: +healing, Int, Spirit, Sta. Cloth only. Note empty slots (free upgrades).
- Random-suffix gear (`<Random enchantment>`) - stats unknown, say so.
- Check `characters/<Char>/<Spec>/Weapons.md` notes (e.g. `Arms/Weapons` / `Prot/Weapons`) - mark Got or link if the item is already an option there.
  A W weapon upgrade that is **not** there yet goes into that note too (row in its level band), then run
  `notes/gear_options.py ... --note` (wow:notes "Gear note") - Mograine's Might sat in the SM notes for a day
  without reaching Arms/Weapons.
- Quest rewards of the dungeon's quests and their follow-ups (FDJ `rewardItems`, e.g. A Tale Spun Around the Fire
  after The Drowned City) count as this dungeon's loot: judge them like drops.
Write them as `- [ ] W — ...` lines at the end of the boss's section / `## Trash` (format above). Then
```
python3 -I loot_note.py "<Dungeon>"
```
-> `notes/<Dungeon> loot.md` (no title; embedded under `## Loot` of the main note, added above `## Notes` if
missing): `## <nr>. <Boss> — <level>` heading per boss, then one banner per item = the full item tooltip, always
visible (scroll, no hover). Header: approx % change for W / P vs what they wear in that slot (BagBrother, incl.
random-suffix stats via the link's bonus IDs; rough weights in `score()`: W Str/Sta/2H DPS/armor/hit/crit,
P healing/mp5/Int/Spi; rings vs the weaker one, 2H vs main + off hand; W skips cloth/leather/1H/off-hands),
"empty slot" or "? random stats". Green = upgrade (>= 5%). Sorted by best upgrade; quest items / recipes dimmed.
BagBrother refreshes on `/reload` / logout - stale gear = wrong %. Drops from AtlasLoot (Forever-only dungeons: trash from ForeverDungeonJournal); item
cards are made for every drop (`notes/gen_cards.py`). Re-run after changing upgrades.

## 5. Interactive map
```
python3 -I interactive_map.py "<Dungeon>" [--slug ...] [--preview <scratchpad>/<slug>-route.png]
```
-> `map/<Dungeon> (interactive).md` (one HTML block, images as data URIs); `## Map` in the main note embeds it.
- **Pins**: boss portraits (site portrait, else the method.gg render, else a numbered badge; rares = silver
  ring). Hover = boss card: TLDR line, ability icons (hover = spell tooltip from `abilities/<Spell>.md`; red frame
  = ej-important, corner badge = role), W/P upgrades (hover = item tooltip). Click = scroll to its banner
  (`data-wm-jump` -> `data-wm-id`, handled by the vault plugin `.obsidian/plugins/wowmap-jump` - notes can't run
  JS; "↑ map" scrolls back).
- **Under the map**: BOSSES banners (portrait + map number, level, `[!boss]` line, TLDR, abilities with role
  badges, the `[!roles]` bullets as shield/cross/sword lines), then TRASH: the kill-order row and a banner per
  `## Trash` line (method.gg render, points, role action lines; dangerous mobs first with a red edge), plus a
  "Trash loot" chip.
- **Quest pins** come from the main note's frontmatter (x/y = % of the map image); `text:` = the pin card lines
  (objective, turn-in, rewards); `guess: true` = dashed ring + "approx. position":
```
pins:
  - {kind: quest, name: Blueleaf Tubers, x: 43, y: 54, guess: true, text: ["Dig 6 Blueleaf Tubers", "→ Mebok Mizzyrix, Ratchet"]}
  - {kind: boss, name: Aggem Thorncurse, x: 70, y: 50, guess: true}   # add/move a boss pin
```
  Add a pin for every in-dungeon quest objective (guess from guide text, mark `guess: true`); when the
  user confirms/corrects a spot, fix x/y and drop `guess`.
- **Route (required)** - `route:` in the main note's frontmatter, drawn as a dashed red line with direction
  arrows under the pins (green "Start" dot at the entrance):
```
route:
  - [50, 95]                          # entrance
  - [48, 70]                          # a point at every corridor bend - the line must not cut through walls
  - {x: 30, y: 52, label: drop down}  # short label where something happens (jump, skip, shortcut, quest item)
  - [22, 40]                          # ... through every boss pin in map-number order
```
  Order = boss numbers on the map (path order from the guides: foreverchanges/method.gg route, "clear order"
  text; optional/rare bosses only as a short detour). Pass through quest pins on the way. Run with `--preview`
  and **Read the PNG**: line stays inside corridors, hits every boss/quest dot in order, no needless
  backtracking - fix points and re-run until it does. Multi-floor: one route through all floors, label the floor
  change (`label: stairs → Floor 2`). Route from guide text, not seen in-game -> tell the user it's a first draft.
  The script prints a WARNING when `route:` is missing.
Regenerate after editing the main note or the map data.

## Styles and quirks
- `gaming/.obsidian/snippets/wow.css`: `.wowmap` / `.wm-*` (map, pins, cards, route `.wm-route`, banners
  `.wm-mob`), `.wowloot` / `.wm-item` (loot note), `[!boss]` / `[!roles]` / `[!tank|healer|dps]` callouts,
  `[!wow|spell]` cards. Cards scale with map width via container queries; pins right of center open left.
- Obsidian restyles HTML inside notes: images become `display: block` (keep `!important` on inline icons), lists
  get its own bullets (banners use plain spans), `text-indent` inherits into inline-blocks.
- Live Preview wraps HTML blocks in widgets with `contain: paint`, and note embeds get `overflow: auto` + a max
  height - both clip popups / scroll; wow.css lifts them for embeds `:has(.wowmap)` / `:has(.wowloot)`. Embeds
  also get an inline `min-height` estimated from the source (huge with data URIs -> empty block) - reset too.
- Item cards: set items' Wowhead tooltips carry a `<div>` piece list - gen_cards turns divs into spans so tags
  balance per line (an unclosed tag in one card breaks every banner after it).
- A note tab holds both Live Preview and Reading view (one hidden) - DOM lookups must pick the visible copy.
- Check layout changes in a headless render first: wrap the generated HTML + wow.css in a page (dark body,
  plus `img{display:block;margin:auto}` to mimic Obsidian), `chromium --headless=new --screenshot`, Read the PNG.
